# Domains

## Purpose

Domains are durable areas of knowledge and inquiry. A domain is not automatically a project, product, or organisational department. It becomes useful when it helps navigate recurring entities, ideas, evidence, and projects.

## Current domains

### ROS2

Established implementation and learning foundation. It contains work on nodes, communication, launch, TF, simulation, control, navigation, manipulation, and system integration.

### Robotics

Established and active practical medium for embodied sensing, control, learning, and cyber-physical integration.

### Cyber-Physical Systems

An exploratory bridge from individual robots toward systems that couple sensing, computation, decision-making, actuation, people, and real environments.

### AI, ML, and Data Science

Exploratory capabilities for perception, modelling, inference, analysis, and decision support. They are not assumed to be appropriate for every project.

### Edge and Distributed Intelligence

An exploratory architectural direction concerned with local knowledge, communication, coordination, delegation, and distributed decisions.

### Nature and Living Systems

The purpose context for future work. It should become a domain only when concrete research, observations, projects, or evidence require durable organisation.

## Domain rules

Each real domain should have a primary README explaining its scope, current relevance, major entities, active questions, important resources, and relationships to projects. Domain-specific documentation standards are added only when the domain repeatedly needs specialized information not already handled by the common framework.
